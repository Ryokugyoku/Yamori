# Yamori

> **PCを知り、PCを守り、次のPCをデータで選ぶ。**
> 完全オフライン・オープンソースのWindows PC管理アプリ

*Yamori（家守／ヤモリ）は「家を守るもの」という意味の日本語です。*

---

## コンセプト

Yamoriは、PCのハードウェアを一つの画面で管理し、限界に近い使われ方をしている部品と、**その原因になっているアプリ**を見つけ出します。そして、数か月分の実際の使用データから、**次のPCを買うときの基準**をわかりやすく示します。

企業では、高価な専用ツール（ライトサイジング／DEX製品）を使って、すでに同じことをしています。Yamoriは、このデータに基づく判断を個人や小さなチームでも使えるようにします。しかも、**データは1バイトもPCの外に出しません。**

### Yamoriの立ち位置

| | 長期間の使用状況を測る | 原因のアプリが分かる | 次のPCの基準を示す | 個人が使える | 完全オフライン |
|---|---|---|---|---|---|
| 企業向けライトサイジング製品 | ✅ | ✅ | ✅ | ❌ | ❌ |
| アップグレード診断Webツール（スペック入力型） | ❌ | ❌ | ✅ | ✅ | — |
| タスクマネージャー／ハードウェアモニター | △ | ✅ | ❌ | ✅ | ✅ |
| **Yamori** | ✅ | ✅ | ✅ | ✅ | ✅ |

## 基本方針

1. **完全オフライン**：外部APIは一切呼ばない。テレメトリ、分析、クラウド連携もなし。データは既定でPCの中に留まる。
   - 記録の保存先は、設定で **OneDrive フォルダー** や **指定したフォルダー** にも変えられる（任意）。Yamori はフォルダーにファイルを書くだけで、同期は OneDrive アプリが行う。Yamori 自身が通信することはない。
   - サインインは **Windows アカウント**（Windows Hello）で、PCの中だけで行う。
2. **オープンソース**：「通信しない」という主張を、誰でもコードで確認できる。
3. **カーネルドライバを使わない**：Windowsが提供する仕組み（WMI、パフォーマンスカウンター、S.M.A.R.T.、GPUメーカーのAPI）だけを使う。WinRing0のような脆弱なドライバは使わない。
4. **誠実な表示**：事実とわかりやすい説明だけを示す。不安をあおる警告や「問題が○件見つかりました。直すには有料版へ」のような表示はしない。
5. **数値には説明をつける**：すべての数値に「何を意味するか」「気にするべきか」を添える。

## 機能とロードマップ

### v1 — ハードウェアの一元管理と、次のPCの基準
- ハードウェア情報の一覧（CPU、メモリ、ストレージ、GPU、バッテリー）
- バックグラウンドで常に監視し、履歴をPCの中に保存
- **負荷時間の分析**：一時的な負荷の山ではなく、各部品が一定の使用率（例：50%超、80%超）を超えていた時間の割合を見る
- **原因アプリの特定**：どのアプリがどの部品をどれだけ使っているか
- 長期的な劣化の傾向（SSDの寿命、バッテリー容量など）
- 大事な変化があったときのローカル通知
- **次のPCのおすすめ**。例：
  > メモリ使用率が80%を超えていた時間は、使っていた時間全体の35%。主な原因はChromeとTeams。
  > 次のPCは32GB以上がおすすめです。

### v1.5 — 通信の見える化（表示のみ）
- アプリごとの通信量と通信先
- 性能と通信をまとめて表示：「このアプリはCPUを○%、通信を△GB使っていて、□□と通信している」
- 遮断はしない。管理者権限も不要

### v2 — 通信のロックダウン
- 許可リスト方式：ユーザーが許可したアプリだけが通信できる
- **Windows標準のファイアウォール**を操作して実現する（独自ドライバは作らない）
- システムに必要な通信の安全な初期設定（Windows Update、Defender、時刻同期、DNS、Microsoft Storeのライセンス確認）
- ワンクリックで元に戻せる**緊急解除**
- 管理者権限が必要な処理は、別の補助プログラム（`Yamori.Guard`）に分ける。画面は通常の権限で動く
- まずはアプリ単位で制御する。接続先（ドメイン）単位の制御は将来の検討課題

## 構成

- **UI**：WinUI 3（Windows App SDK）
- **言語**：C# / .NET 10
- **対象OS**：Windows 10 / 11

```
Yamori.slnx
├─ Yamori.App          WinUI 3の画面
├─ Yamori.Core         データ収集、集計、おすすめを出すロジック
├─ Yamori.Core.Tests   Coreのテスト
└─ Yamori.Guard        （v2）ファイアウォール制御用の補助プログラム（管理者権限）
```

### データの取得元（v1はドライバも管理者権限も不要）
- WMI / CIM
- Windowsのパフォーマンスカウンター（GPUエンジンのカウンターを含む）
- Windowsが提供するストレージのS.M.A.R.T.・健康状態の情報
- ファームウェアの SMBIOS テーブル（`GetSystemFirmwareTable`。ファン・電源ユニットの情報）
- DirectX の DXCore（GPU の正確なビデオメモリと、内蔵 GPU かどうか）
- ディスクへの属性の問い合わせ（`\\.\PhysicalDriveN` をアクセス権 0 で開き、`IOCTL_STORAGE_QUERY_PROPERTY` でストレージの温度を読む。ディスクの中身は読めない開き方なので管理者権限は不要）
- 使える場合はGPUメーカーのAPI

### 現在できること
- [x] 部品別のハードウェア一覧（管理者権限・ドライバー不要）
  - **CPU**：コア／スレッド数、P コア・E コアの内訳、定格クロック、キャッシュ、ソケット、**内蔵 GPU**
  - **マザーボード**：メーカー・型番・リビジョン、筐体の形、BIOS／UEFI のバージョンと公開日
  - **メモリ**：合計容量と規格（DDR4／DDR5 など）、スロットの空き、最大容量、モジュールごとの速度・メーカー・型番
  - **GPU**：正確なビデオメモリ（DXCore、4GB を超えても正しい値）、共有メモリ、ドライバーと日付、解像度とリフレッシュレート
  - **ストレージ**：容量・種類・接続方式・健康状態、ドライブごとの空き容量、ファームウェア、**温度**（ディスクへの直接の問い合わせ。NVMe・SATA の多くで一般ユーザーのまま読める）。消耗度・通電時間は Windows が公開している場合のみ
  - **ファン**：ファームウェア（SMBIOS）が報告する冷却装置の種類・状態・公称回転数
  - **電源ユニット**：今の電源（AC／バッテリー）、ファームウェアが報告する電源ユニット、バッテリーの劣化度と充放電回数
  - **ネットワーク**：ハードウェアのアダプターの製品名・接続方式（有線 LAN／Wi-Fi など）・接続状態・リンク速度・ドライバー。仮想アダプターは表示しない。MAC アドレス・IP アドレス・SSID は読み取らず、表示も保存もしない
- [x] リアルタイム表示（1 秒ごと。画面を開いている間だけ測り、記録はしない。管理者権限・ドライバー不要）
  - **CPU**：使用率（タスク マネージャーと同じ `% Processor Utility`。全体・論理プロセッサごと）、動作時間の割合（`% Processor Time`）、ユーザー／カーネル／割り込み／DPC の内訳、今のクロックと定格比、性能の制限、消費電力（RAPL）、スレッドの切り替え・システム コール・割り込みの回数、プロセス・スレッド・ハンドルの数、起動してからの時間
  - **RAM**：使用中・使用可能、コミット済みと上限、キャッシュ・スタンバイ・変更済み・空きの内訳、カーネルのプール、ページ フォールト、ページ ファイルの使用率
  - **GPU**：使用率（エンジンの種類ごと）、温度、消費電力（定格比）、コア・メモリのクロック、ファン、専用・共有メモリの使用量、帯域（D3DKMT。ドライバーが報告する場合）
  - **HDD・SSD**：アクティブな時間、読み書きの速さと回数、応答時間、待ちの要求、**温度**、ドライブごとの空き容量
  - **ネットワーク**：つながっているハードウェアのアダプターごとの受信・送信の速さ、リンク速度、使用率（送受信の合計 ÷ リンク速度）。仮想アダプター（VPN、Hyper-V、WAN Miniport など）・ループバック・未接続のアダプターは表示しない
  - **電源ユニット**：今の電源、電力量計（CPU の RAPL）、GPU の消費電力、バッテリーの残量・残り時間・充放電の速さ
  - **ファン**：GPU のファンの回転数、ACPI 温度センサーと熱による制限
  - **アプリ**：CPU・GPU・読み書き（入出力）のそれぞれで多く使っているアプリの上位 5 件（同じ名前のプロセスはまとめて集計。保護されたプロセスも含む）
- [x] CPU・メモリ使用率の記録（10秒ごと、既定では `%LOCALAPPDATA%\Yamori\history` に日ごとのCSVで保存）
- [x] 負荷時間の分析と、次のPCのおすすめ（CPUのスレッド数、メモリ容量）
- [x] メモリを多く使っているアプリの一覧（同じアプリの複数プロセスはまとめて集計）
- [x] Windows アカウントでのサインイン（Windows Hello。未設定のPCではサインイン中のアカウントのまま続行）
- [x] 記録の保存先の選択（このPC／OneDrive／指定フォルダー。PCごとに `Yamori\<PC名>\history` へ保存し、切り替え時はこれまでの記録をコピー）
- [x] 日本語・英語・スペイン語の表示（既定は Windows の言語。その他の言語では英語）
- [x] Windows のライト／ダーク モードへの追従（開いたままでも切り替わる）

### まだできないこと
- [ ] アプリを閉じている間の記録（今はYamoriを開いている間だけ記録する）
- [ ] アプリごとのCPU使用率の履歴と、それに基づく原因アプリの特定（今のアプリごとの使用量はリアルタイム表示で見られるが、記録はまだしない）
- [ ] GPU・ストレージ・ネットワークの使用率、SSD寿命の長期的な傾向
- [ ] アプリごとの通信量（v1.5）
- [ ] ローカル通知

既知の制限：
- マザーボードにつながったファンの回転数と CPU の温度は、カーネルドライバーなしでは Windows から読めないため表示しない（基本方針 3）。GPU のファン・温度は、ドライバーが Windows に報告している場合だけ表示する。
- デスクトップ PC の電源ユニットの多くは出力を Windows に報告しないため、PC 全体の消費電力は表示できない（CPU・GPU が自分で測っている値だけを表示する）。
- 自作 PC 用の電源ユニットの多くは容量（W）をマザーボードに伝えないため、表示できないことが多い。
- DXCore がない古い Windows 10（2004 より前）では、GPU のビデオメモリが 4GB を超えると正しく表示されないことがある。
- ストレージの温度は、ディスクとドライバーが温度の問い合わせに対応している場合だけ表示する。仮想ディスクや一部の USB 接続のケースでは表示されない。
- アプリごとの「読み書き」は `IO Read/Write Bytes/sec` で、ファイルだけでなくデバイスやネットワークとのやり取りも含む。そのためタスク マネージャーの「ディスク」の列（ETW で数えたディスクだけの値）とは一致しない。
- アプリごとの CPU 使用率は動作時間（`% Processor Time`）を PC 全体の割合にしたもので、ブースト中はタスク マネージャーのアプリの値より低く出ることがある。
- 記録（10 秒ごとの CSV）と負荷時間の分析の CPU 使用率は、今は `GetSystemTimes`（動作時間）のまま。リアルタイム表示の使用率（`% Processor Utility`）とは、ブースト中や省電力でクロックが下がっているときに値が違う。
- Wi-Fi のリンク速度は接続時に決まった速さで、実際に出せる速さはふつうそれより低い。そのため Wi-Fi の使用率は低めに出る。

### コードの構成（Yamori.Core）

| フォルダー | 役割 |
|---|---|
| `Hardware/` | 部品の情報のモデル（CPU・マザーボード・メモリ・GPU・ストレージ・ファン・電源ユニット・ネットワーク）と、それを読み取る処理（`Readers/` に部品ごとに1クラス）。情報源は `Wmi/`、`Smbios/`（ファームウェアのテーブル）、`Graphics/`（DXCore）、`Topology/`（P コア・E コア）、`DeviceIo/`（ディスクへの IOCTL。ストレージの温度） |
| `Monitoring/` | 使用率を測るセンサーと、定期的に記録する監視処理 |
| `Realtime/` | リアルタイム表示用の測定。`Counters/`（PDH のパフォーマンスカウンターと、インスタンス名の読み解き）、`Gpu/`（D3DKMT の GPU センサー）、`Sources/`（Win32 API・WMI）、`Collectors/`（部品ごと・アプリごとに 1 クラス） |
| `Storage/` | 履歴の保存（CSV）と、保存先（このPC／OneDrive／指定フォルダー）の切り替え |
| `Settings/` | ユーザー設定（保存先、表示言語）と、その保存（`%LOCALAPPDATA%\Yamori\settings.json`） |
| `Localization/`, `Resources/` | 表示文字列（`*.resx`。英語が既定、`.ja`・`.es` が翻訳） |
| `Processes/` | プロセスの使用量（メモリ、CPU・GPU・入出力）の取得と、アプリ単位の集計 |
| `Analysis/` | 負荷時間（しきい値を超えていた時間の割合）の分析 |
| `Recommendations/` | 次のPCのおすすめの判定（部品ごとの判定方針） |
| `Formatting/` | 数値やおすすめを、説明つきの文章にする処理 |
| `Reports/` | 上記をまとめて画面用のレポートを作る処理 |
